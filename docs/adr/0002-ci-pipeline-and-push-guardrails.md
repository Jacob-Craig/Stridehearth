# 0002. Continuous Integration Pipeline, Mechanical Code Linting, and Multi-LLM Push Guardrails

Status: superseded in part by ADR-0005. The agent push-governance decisions below (the `CONFIRM_PUSH`/TTY guard in `.githooks/pre-push` and the Claude Code hook blocking every `git push`) are replaced by [ADR-0005](0005-agents-may-push-feature-branches.md). The CI pipeline, ktlint, pre-push verification, main/master rejection, and automated hook registration decisions still stand. The 7-day Boot jar artifact archived from `main` is replaced by the container images of [ADR-0009](0009-trunk-based-releases-pulled-from-a-registry.md) (#19).

Mechanical code style linting, multi-layered agent push guardrails, and parallel GitHub Actions continuous integration are implemented together to preserve repository health, eliminate subjective code style debate, prevent accidental pushes of broken or unverified code, and enforce safety boundaries for autonomous AI coding agents without impeding developer velocity.

## Considered Options

- **Kotlin Linting Engine**: Selected `org.jlleitschuh.gradle.ktlint` (version 14.2.0) with standard ktlint rules. Rejected Detekt (focused on static analysis and complexity metrics rather than pure mechanical formatting; can be introduced later if AST rules are needed) and Spotless (uses Ktfmt/ktlint via wrapper with slower configuration and less idiomatic Kotlin Gradle DSL integration). ktlint delivers automatic formatting (`ktlintFormat`), tight Gradle task lifecycle integration (`check` dependency), and direct alignment with official Kotlin coding conventions.
- **Push Guardrails**: Selected a tracked Git `pre-push` hook (`.githooks/pre-push`) registered automatically via Gradle (`installGitHooks` attached to compilation). Rejected `pre-commit` hooks because running checks on every commit impedes local commit velocity, disrupts WIP experimentation, and frustrates micro-commits. Rejected server-side GitHub branch protection alone because branch protection requires administrative repository settings, does not catch issues prior to pushing, and wastes cloud CI minutes on trivial formatting failures.
- **Multi-LLM Push Safety Governance**: Selected a defense-in-depth model combining an explicit governance policy in `AGENTS.md` with an active Claude Code `PreToolUse` hook interceptor (`.claude/hooks/block-dangerous-git.sh`) and an interactive TTY detection guard in `.githooks/pre-push`. Rejected reliance solely on LLM prompt instructions, as autonomous subagents or external tools can ignore prompt guidelines under complex context pressure.
- **CI Pipeline Topology**: Selected parallel `lint` (`ktlintCheck`) and `test` (`check`) jobs with conditional executable JAR packaging (`bootJar`) restricted to clean merges on `main`. Rejected a monolithic sequential pipeline because running linters in parallel delivers immediate sub-minute feedback while Testcontainers-backed integration tests spin up Docker containers.

## Consequences

- **Zero-Tolerance Mechanical Formatting**: All Kotlin source files are mechanically formatted via ktlint. Style debates in PR reviews are eliminated. Filename conventions for multi-class DTO files are standardized via `.editorconfig` (`ktlint_standard_filename = disabled`).
- **Fast Pre-Push Verification**: The pre-push hook runs `./gradlew --no-daemon ktlintCheck testClasses frontendCheck` (originally `ktlintCheck testClasses`; `frontendCheck` was added with the SPA in ADR-0004), verifying syntax, types, and formatting across main, test, and frontend sources before code leaves the local machine without incurring Docker Testcontainers overhead. `frontendCheck` aggregates `frontendLint` (`biome check`, lint + format), `frontendTypecheck` (`tsc --noEmit`), `frontendTest` (`vitest run`), `frontendCodegenCheck` (generated API client freshness), and `frontendBuild` (`vite build`). `./gradlew check` runs all of these plus `ktlintCheck` and `test`; `./gradlew bootJar` runs `frontendCheck` and packages the SPA.
- **Main Branch Protection**: Direct pushes to `refs/heads/main` or `refs/heads/master` are unconditionally rejected by the pre-push hook, enforcing feature branch pull request workflows.
- **Autonomous Agent Push Prevention**: Headless, non-interactive execution of `git push` is blocked at the Git hook level unless explicitly authorized via `CONFIRM_PUSH=true`. Claude Code bash invocations matching dangerous git commands (`git push`, `git reset --hard`, `git clean -fd`, etc.) are intercepted with exit code 2 before execution.
- **Automated Hook Registration**: Any developer, CI agent, or container running `./gradlew compileKotlin`, `./gradlew check`, or `./gradlew build` automatically configures `core.hooksPath = .githooks` idempotently.
- **Optimized GitHub Actions CI**: Pull requests and main pushes trigger parallel `lint` (`ktlintCheck`), `frontend` (`npm ci`, `biome check`, `tsc --noEmit`, `vitest run`, `codegen:check`), and `test` (`./gradlew check`) jobs with Gradle dependency caching (`actions/setup-java@v4`) and npm caching keyed on `frontend/package-lock.json` (`actions/setup-node@v4`, Node version from `frontend/.nvmrc`). Merge commits to `main` build (after all three jobs pass) and archive the Spring Boot production JAR with a 7-day retention policy to respect GitHub storage quotas.
- **Guardrail Tests**: `GitHubActionsWorkflowTest`, `PrePushHookEnforcementTest`, `KtlintEnforcementTest`, and `GradleVerificationLifecycleTest` assert the Kotlin and TypeScript gates above, including that a Biome, `tsc`, or Vitest failure rejects a push.
